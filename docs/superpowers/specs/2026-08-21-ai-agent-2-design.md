# AI 智能体 2.0 设计

## 目标

把现有右侧 AI 助手从“带命令执行能力的聊天框”升级为能够持续理解当前服务器、自动收集证据、按权限执行、验证结果并给出结论的个人运维智能体。

设计同时满足三个目标：

- **更会解决问题**：不把命令交回用户手动执行，能够从诊断到验证形成闭环。
- **更少操作**：自动携带当前主机、最近命令和异常信息，只在权限策略要求时询问用户是否执行。
- **更简约**：保留一条清晰对话时间线，状态和操作就近显示，复杂证据按需展开。

第一阶段优先完成上下文编排、结构化回复和排障状态管理；第二阶段再以这些稳定能力为基础简化右侧界面。这样不会为了改外观而继续堆叠孤立功能。

## 非目标

- 不增加团队、工单、多人审批或角色管理功能。
- 不提供绕过权限策略的“完全无人值守高风险执行”。
- 不把密码、私钥、Token 或完整敏感配置发送给模型或写入新的本地记录。
- 不替代终端、脚本管理、批量运维和日志模块；AI 只负责理解和协调这些入口。
- 不展示模型的隐藏推理过程，只展示可核对的结论、证据、行动和结果。
- 本设计阶段不打包安装程序。

## 设计原则

1. **上下文自动获取**：用户描述问题即可，已知的服务器和命令信息不再重复询问。
2. **证据先于结论**：结论必须关联真实命令结果、连接状态或用户提供的内容。
3. **一步一验证**：每次变更执行后自动运行只读验证，失败即停止后续依赖步骤。
4. **权限边界独立**：模型只能提出操作，最终是否执行继续由现有权限策略裁决。
5. **渐进披露**：默认只显示结论和下一步，原始输出、风险说明和完整过程按需展开。
6. **会话与连接解耦**：SSH 重连、右侧面板收起或页面切换不得清空当前排障任务和对话。

## 当前基础与主要缺口

当前项目已经具备：

- `src/stores/chat.ts`：多对话及 `localStorage` 持久化。
- `src/utils/ai-chat.ts`：流式对话、`<execute_command>` 解析、SSH 执行和失败重试。
- `src/utils/ops-permission.ts`：只读、受控、高权限和自定义四种策略，以及风险分类。
- `src/stores/opsAgent.ts`：权限配置、命令审计和有限输出脱敏。
- `src/utils/operation-records.ts`：终端、AI、脚本和批量操作的统一记录与敏感信息清洗。
- `src/components/AiChat.vue`：终端、文件、脚本、诊断、自愈和编排入口。

主要缺口是这些能力没有形成统一任务：模型每次请求只获得基础服务器信息和聊天历史，缺少最近操作、工作目录、连接恢复、当前模块和排障进度；命令执行结果虽然会再次发送给模型，但 UI 仍表现为连续文本，用户难以快速判断智能体当前在分析、等待授权、执行还是验证。

## 总体架构

```text
用户问题 / 模块联动
        ↓
AgentContextAssembler
        ↓
受限、脱敏的 AgentContextSnapshot
        ↓
AI 对话流 + AgentResponseParser
        ↓
TroubleshootingSessionStore
        ↓
提出行动 → 权限裁决 → SSH 执行 → 写入证据 → 自动验证
        ↑                                      ↓
        └────────────── 继续分析 ──────────────┘
```

### 1. 上下文编排器

新增 `src/utils/agent-context.ts`，集中构建发送给模型的上下文，避免继续在 `AiChat.vue` 和提示词中拼接零散字符串。

```ts
export interface AgentContextSnapshot {
  capturedAt: number
  host: {
    id: string
    name: string
    address: string
    port: number
    username: string
    connectionStatus: string
    sessionGeneration?: number
  } | null
  workspace: {
    view: 'terminal' | 'files' | 'logs' | 'ops' | 'scripts' | 'history' | 'unknown'
    cwd?: string
    selectedPath?: string
    selectedScriptId?: string
  }
  recentOperations: AgentOperationContext[]
  activeIssue?: {
    id: string
    summary: string
    state: TroubleshootingState
  }
  permission: {
    level: 'readonly' | 'controlled' | 'elevated' | 'custom'
  }
}
```

编排规则：

- 默认只包含当前主机，批量运维或脚本明确选择多台主机时才加入多目标信息。
- 读取当前主机最近 8 条操作记录；单条只保留命令、状态、目录和必要输出。
- 上下文总文本控制在 24 KB 内，单条输出最多 4 KB，优先保留最近错误和当前问题直接相关的记录。
- 复用 `redactOperationText`，并额外过滤私钥块、Authorization、Cookie、数据库连接串和常见云凭据。
- 密码、私钥、密钥口令和模型 Token 永远不进入快照。
- 快照只在用户发送消息、模块主动发起 AI 分析或智能体完成一次命令后重建，不持续监控或上传。

### 2. 排障会话状态

新增 `src/stores/troubleshooting.ts`，一个 AI 对话对应一个可选排障任务。状态定义为：

```ts
export type TroubleshootingState =
  | 'idle'
  | 'assessing'
  | 'collecting'
  | 'awaiting_authorization'
  | 'executing'
  | 'verifying'
  | 'resolved'
  | 'blocked'
  | 'cancelled'
```

任务保存以下最小信息：问题摘要、关联主机、当前状态、已确认事实、待执行行动、最近错误、开始和更新时间。原始大段终端输出仍放在现有操作记录中，通过记录 ID 关联，避免对话和状态重复存储。

状态随对话一起本地持久化，SSH 自动重连只更新连接代次和状态，不创建新任务、不清空消息。用户新建对话、删除对话或在数据管理中清除 AI 数据时才移除对应任务。

状态转换：

```text
idle → assessing → collecting → awaiting_authorization
                    ↑                    ↓
                    └──── executing ←────┘
                              ↓
                          verifying
                         ↙         ↘
                     resolved     assessing / blocked
```

- 只读命令被策略允许时可从 `collecting` 直接进入 `executing`。
- 变更、未知或高风险操作按照现有策略进入授权流程。
- 用户拒绝操作后，智能体优先寻找只读替代方案；没有替代方案才进入 `blocked`。
- 超时或连接级错误作为证据记录，底层重连后重试一次；仍失败时说明准确错误，不显示笼统的“无输出”。

### 3. 回复契约与兼容解析

新增 `src/utils/agent-response.ts`。模型继续输出可读 Markdown，但在需要行动时附带一个内部机器可读块，避免把整条回复强制改成 JSON，影响流式显示。

```text
结论：磁盘空间正常，异常集中在 nginx 服务未启动。

证据：nginx 为 failed，80 端口没有监听。

下一步：读取最近 80 行 nginx 日志。

<agent_action>{"id":"action-1","kind":"command","command":"journalctl -u nginx -n 80 --no-pager","purpose":"确认启动失败原因"}</agent_action>
```

解析器返回：

```ts
export interface AgentResponse {
  displayMarkdown: string
  status: 'informational' | 'needs_action' | 'resolved' | 'blocked'
  conclusion?: string
  evidence: string[]
  actions: AgentAction[]
}
```

兼容规则：

- 第一阶段同时识别现有 `<execute_command>` 与新 `<agent_action>`，保证已有模型配置不突然失效。
- 结构块格式错误时完整保留普通 Markdown，不丢消息、不执行无法解析的命令。
- 机器块不直接显示在对话正文中，UI 只呈现行动摘要和按钮。
- 模型给出的“风险等级”仅作为说明，真实风险始终由 `ops-permission.ts` 重新分类。
- 不依赖模型输出隐藏思考、置信度或长篇过程。

### 4. 执行协调器

新增 `src/utils/agent-execution.ts`，把目前散落在 `AiChat.vue`、普通工具循环、自愈流程中的公共执行步骤统一为：

1. 接收结构化行动和当前上下文快照。
2. 调用 `opsAgentStore.decide` 获取真实策略结果。
3. `allow` 直接执行，`confirm` 单次询问，`double_confirm` 二次询问，`deny` 返回受阻证据。
4. 通过 `sshExecFull` 执行，并保留 stdout、stderr、退出码和超时状态。
5. 写入现有操作记录和审计记录。
6. 根据行动中的验证命令，或让模型生成安全只读验证，再执行验证。
7. 把结果以内部证据消息交回模型，继续当前任务，而不是在对话中重复创建用户卡片。

执行协调器不自行扩大权限。高风险操作仍永远二次确认；`readonly` 模式下非只读命令仍拒绝；`controlled`、`elevated` 和 `custom` 的具体行为完全复用现有策略。

为避免无限循环，每个用户请求最多执行 12 个行动、最多 8 轮模型续答。达到上限时进入 `blocked`，显示已经得到的证据和继续排查按钮，由用户主动继续。

## 对话与交互设计

右侧面板继续沿用现有可收起、可拖拽宽度和全局可拖动 AI 球，不新增常驻导航。

### 顶部

顶部只保留：

- “运维助手”名称和当前主机短名。
- 一个低干扰状态文字：分析中、等待执行、验证中或已完成。
- 历史对话和新建对话入口收进同一个轻量菜单。
- 权限等级显示为小型状态入口，点击才打开完整权限选择。

监控、自愈、编排、审计等现有能力不再并排占据一整行图标；只有当前任务实际使用相关能力时，才在消息内显示对应入口。

### 消息时间线

- 用户消息和 AI 结论使用干净文本块，不使用大面积高饱和背景。
- AI 回复默认显示“结论、关键证据、下一步”三部分；没有内容的部分不渲染标题。
- 原始命令输出折叠在“查看证据”中，默认显示命令、状态和一行摘要。
- 同一次排障的多次执行归入一个任务段落，不为每轮结果重复一张消息卡。
- 完成后显示一句结论和可选的“保存为快照”，不自动弹出报告面板。

### 行动卡

行动卡紧跟在提出该行动的 AI 回复下方，只包含：

- 操作目的。
- 一行命令预览。
- 风险标签。
- 主按钮“执行”；可选菜单中提供“编辑后执行”和“复制”。

只读且当前权限允许自动执行时，不短暂闪现确认卡，直接切换为“执行中”；变更操作只询问一次，高风险操作保留二次确认。用户不需要手动复制命令，也不需要把输出再次粘贴给 AI。

### 输入区

输入区保持一行至四行自适应，默认只有输入框和发送按钮。服务器、文件、脚本和终端操作通过已有模块联动自动成为上下文，不再把整段上下文复制成醒目的用户消息。输入区上方仅在必要时显示一个可删除的上下文摘要，例如“8.152.205.112 · 最近 3 条命令”。

## 提示词策略

运维智能体提示词拆成三层，避免当前单个长字符串继续增长：

1. **稳定角色规则**：中文、专业、不得让用户手动执行、安全边界和回复格式。
2. **动态上下文**：由 `AgentContextAssembler` 生成的服务器、最近操作和任务状态。
3. **当前请求**：用户输入或模块联动内容。

稳定规则明确要求：

- 先用有界只读命令获取证据，再判断根因。
- 不把“命令无输出”解释为断线。
- 不重复执行已经得到相同结果的命令。
- 变更前说明作用和影响，变更后必须验证。
- 无法继续时明确指出缺少的权限、连接或证据，不能虚构结果。
- 回复先给短结论，详细输出按需展开。

## 本地数据与隐私

- 排障任务使用新键 `ai-troubleshooting-sessions-v1`，只保留最近 50 个任务，每个任务只保存摘要和记录引用。
- 对话继续使用现有 `ai-chat-conversations`，操作输出继续使用 `operation-records-v1`，审计继续使用现有键，不复制原始数据。
- 数据管理页的“清除 AI 与历史”同时删除排障任务；导出备份时只导出脱敏后的摘要和现有允许导出的业务数据。
- 模型请求仅包含本次生成的上下文快照。快照不额外落盘，不后台上传。
- 用户删除单条对话时同步删除对应排障任务，但不自动删除仍可能被命令历史使用的操作记录。

## 异常与恢复

- **SSH 重连**：任务状态和对话不变；恢复后先检查上一行动是否已有完整结果，不能盲目重复变更。
- **命令超时**：保留部分输出并标为超时，优先改用带 `head`、时间范围或 `--no-pager` 的有界命令。
- **命令无输出**：显示“执行成功，无输出”或实际退出码，继续按业务含义分析。
- **模型请求失败**：保留用户消息、上下文摘要和当前任务状态，提供“重试分析”，不重复执行已经成功的行动。
- **结构解析失败**：展示普通回复，禁止执行无法识别的结构块。
- **用户停止**：中止模型流和待执行行动，已完成证据保留；用户可以从当前任务继续。
- **面板关闭或页面切换**：不取消已开始的模型请求和执行；状态在重新打开面板后恢复。

## 分阶段交付

### 第一阶段：问题解决核心

- 实现上下文编排器、脱敏和预算控制。
- 实现排障任务 store 与连接无关的状态持久化。
- 实现回复契约、兼容解析器和执行协调器。
- 将普通 AI 命令、自愈验证和模块联动统一接入任务状态。
- 保持现有 UI 基本布局，只增加必要状态，降低一次改动范围。

### 第二阶段：极简交互

- 将右侧对话重构为单一任务时间线。
- 合并顶部入口，移除长期占位的图标和重复卡片。
- 加入紧凑行动卡、证据折叠和上下文摘要。
- 校验明暗主题、窄宽度、拖拽宽度和全局 AI 球遮挡。

### 第三阶段：质量评估

- 建立固定故障样例：磁盘满、服务启动失败、端口冲突、DNS 异常、权限不足、命令超时和 SSH 重连。
- 记录是否正确采证、是否重复执行、是否错误要求用户手动操作、是否完成验证。
- 根据失败样例调整上下文选择和稳定提示词，而不是继续添加零散按钮。

## 测试策略

1. **上下文单元测试**：当前主机筛选、最近错误优先、24 KB 总预算、单条 4 KB 截断、敏感信息脱敏。
2. **状态机单元测试**：只读自动执行、变更等待授权、拒绝后替代、执行失败、验证失败、用户取消和最终解决。
3. **解析器单元测试**：新行动块、旧 `<execute_command>`、多行动、流式不完整块、非法 JSON 和纯 Markdown 回退。
4. **权限回归测试**：四种权限等级、自定义主机规则和高风险永远二次确认。
5. **集成测试**：命令结果自动回传、执行后验证、超时改用有界命令、自动重连后保持任务和消息。
6. **UI 回归测试**：亮色与暗色主题、窄面板、左右拖拽、长命令、长输出、空状态和面板收起恢复。
7. **项目验证**：运行已有测试、类型检查和前端构建，并启动开发服务检查编译及启动报错；不在本任务中生成安装包。

## 验收条件

- 用户说“帮我看看 nginx 为什么启动不了”时，智能体自动知道当前服务器，并先执行有界只读诊断，不要求用户复制命令。
- 命令执行后结果自动回到同一任务，AI 给出与真实输出对应的结论；需要变更时只显示一张就近行动卡。
- 变更获准并执行后自动验证；验证失败时停止依赖步骤并重新分析。
- SSH 自动重连、右侧面板关闭再打开或切换业务页面后，对话和排障进度仍存在。
- 首次无输出、退出码非零、超时和连接错误均使用准确状态，不再统一显示“无输出”或误称断线。
- 任何模型请求都不包含密码、私钥、密钥口令或 Token。
- malformed 结构回复只作为普通文字显示，绝不误执行。
- 默认界面只显示必要的主机、状态、结论、下一步和输入区；证据、审计和复杂功能按需打开。
