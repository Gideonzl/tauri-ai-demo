# 运维智能体：权限与智能诊断设计

**日期：** 2026-07-29
**状态：** 已确认，第一阶段待实施

## 目标

将现有“运维助手”升级为安全、可解释、可审计的运维智能体。第一阶段先建立权限边界和智能诊断工作流；后续的故障自愈与多机编排必须复用该边界，不能绕过它。

用户是非专业运维人员。智能体应主动采集信息、解释风险并给出推荐操作；用户只需要在需要授权时确认，不应被要求打开终端或复制粘贴命令。

## 交付顺序

1. **权限与智能诊断（本阶段）**：权限档位、命令分类、确认界面、审计日志、关联式诊断。
2. **故障自愈（下一阶段）**：把诊断结论转化为可审查、可验证、可中止的修复计划。
3. **多机编排（第三阶段）**：按主机范围和并发限制执行巡检、灰度变更与结果汇总。

## 方案选择

采用“前端策略引擎 + 后端审计数据结构预留”。

- 仅依赖系统提示词不能形成安全边界，因此不采用。
- 本阶段在前端工具调用入口强制分类和拦截，能复用当前“确认后自动执行”的链路，并能立即交付清晰的用户界面。
- Rust 后端将在后续阶段成为最终的强制执行点；本阶段先使用统一的策略数据模型和审计事件，避免接口重做。

## 权限模型

### 1. 只读巡检

- 仅允许无副作用的系统信息、日志、服务状态、网络状态和配置读取命令。
- 不弹确认框，允许智能体自动执行。
- 任何无法确定为只读的命令均拒绝执行，并提示切换权限档位。

### 2. 受控执行（默认）

- 所有只读命令自动执行。
- 普通变更命令须逐条确认；确认后自动通过 SSH 执行。
- 高风险命令仍须二次确认，二次确认界面必须说明风险和影响范围。

### 3. 高权限运维

- 允许服务重启、部署、软件包管理、配置修改和受控的进程操作。
- 高风险命令不自动执行，始终二次确认。
- 删除、格式化、递归删除、权限/账户/SSH 配置修改、关机/重启、防火墙规则清空等命令属于高风险。

### 4. 自定义策略

- 用户可针对命令类别和主机范围设置“允许自动执行 / 需要确认 / 拒绝”。
- 初版保存于本地配置；规则匹配按“拒绝优先、高风险优先、范围越具体优先”处理。
- 自定义规则不能把固有高风险命令降为自动执行。

## 命令分类与决策

策略引擎为每条工具命令输出：类别、风险级别、理由、是否允许、确认次数和适用权限。

类别包括：

- `read_only`：`df`、`free`、`ps`、`systemctl status`、`journalctl`、`ss`、`cat` 等读取操作。
- `change`：服务启动/停止/重载、软件安装、配置写入、容器变更等。
- `high_risk`：递归删除、磁盘/分区操作、账户与权限修改、远程访问配置、防火墙修改、重启/关机、危险的 shell 重定向或命令替换。
- `unknown`：无法安全判定的命令。只读巡检下拒绝；其他档位至少要求确认。

命令经由策略引擎后才可调用 SSH。策略拒绝、用户拒绝、连接错误和命令失败均成为审计事件，并由智能体用清晰中文说明下一步，不要求用户手动运行命令。

## 用户界面与交互

- 在运维智能体顶部增加权限档位按钮，显示当前档位和颜色状态。
- 点击后打开权限面板，简要说明各档位的能力和限制；默认选中“受控执行”。
- 执行前的确认框显示命令、风险标签、风险原因、目标主机、预计影响和确认要求。
- 高风险二次确认不通过输入任意文本来增加门槛；使用第二个明确的“仍要执行”按钮，避免用户因陌生命令被迫手打。
- 增加近期审计抽屉：时间、主机、命令摘要、策略判定、确认结果、退出状态与输出摘要。敏感输出不写入审计。

## 智能诊断工作流

智能体在用户描述故障或发起诊断时按以下阶段推进：

1. **建立上下文**：确认当前 SSH 会话和目标主机；没有连接时明确说明需要先连接，不虚构执行结果。
2. **安全采集**：自动执行有界只读命令，复用巡检、服务检查、日志和网络模块，避免无限制日志读取。
3. **关联分析**：把健康分、失败服务、资源异常、最近错误日志和监听端口归并成按严重度排序的假设。
4. **行动计划**：输出“现象、可能根因、证据、建议操作、风险、验证方式”。变更操作只在用户确认后执行。
5. **执行与验证**：每个已批准步骤执行后自动运行相应验证命令；失败时停止后续变更，保留证据并给出安全的下一步。

## 数据模型与持久化

- `PermissionLevel`：`readonly`、`controlled`、`elevated`、`custom`。
- `CommandClassification`：命令、类别、风险、理由、要求确认次数、策略结果。
- `AuditEvent`：事件 ID、时间、主机 ID/名称、命令摘要、分类、策略结果、用户确认结果、执行状态、退出码和脱敏输出摘要。
- 用户权限档位、自定义规则和审计事件保存到本地；审计事件按数量和时间滚动清理，避免无限增长。

## 错误处理与安全边界

- SSH 断连时使用既有自动重连与一次重试；仍失败则记录连接错误并停止当前步骤。
- 对命令超时、空输出和非零退出码分别记录，不把“无输出”误报为连接中断。
- 高风险和未知命令永不因 AI 的文字指令而自动放行。
- 任何批量或自愈流程必须逐主机、逐步骤经过同一策略判定；禁止通过直接调用 SSH 绕过策略。

## 验证标准

- 为命令分类与权限决策添加可重复的单元/静态回归测试：只读、普通变更、高风险、未知命令及自定义规则覆盖。
- 验证只读档位拒绝变更命令，受控档位需要确认，高权限档位对高风险命令仍要求二次确认。
- 验证审计记录包含策略结果但不保存完整敏感输出。
- 执行前端构建、Rust 检查、运维智能体回归检查，并实际启动桌面应用检查启动错误。

## 非目标

- 本阶段不自动执行修复、不执行跨主机编排、不创建远程账户或密钥。
- 本阶段不把前端规则视为服务端安全边界；后续阶段会将同一策略下沉到 Rust 命令入口。
